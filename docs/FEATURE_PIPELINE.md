# Feature-first 三阶段合成

新入口 `solve-features` 实现独立的核心搜索策略。旧 R2 入口保持可用，便于对照。本实现不是旧求解器前面的排序启发式，也不会在第三阶段失败后偷偷回退到整场景 I→O 搜索。

```powershell
cabal --config-file=scripts/cabal.config run latis --offline -- solve-features --task data/03560426.json --out results/features/03560426 --budget 20000 --construction-budget 20000 --composition-depth 2
cabal --config-file=scripts/cabal.config test feature-pipeline-tests --offline --test-show-details=direct
```

## 表示与阶段

I 和 O 均使用同一个 canonical encoder 和同一组带类型的 observer。特征用语义名称标识，不用第几个物体作为身份。最小可解码的目标特征是画布宽、高、背景色、物体列表；额外的对象宽、高、颜色和五种锚点作为跨特征来源。每个特征保存所有训练案例的取值向量。只有在每个案例均有定义的 observer 才进入该侧的表示。

严格按以下顺序处理尚未解决的目标特征：

1. **1A**：同名、同类型特征在所有案例上相等，记录 identity。
2. **1B**：搜索类型检查通过的闭合 `P : Ti -> Ti`，要求同一个 P 在所有案例成立。
3. **2A**：在其他同类型特征中寻找所有案例均相等的来源。
4. **2B**：尝试其他同类型来源和 P。1B 学到的程序按类型优先复用，但必须对新来源的完整案例向量重新验证。
5. **3**：关闭变换搜索，对剩余部分归纳输出构造规则，保留前面已经确定的特征。最终从输入执行完整 decoder，并对每个原始训练网格做 exact verification。

`Program` 保存特征规则，不保存训练场景。推理只接受一个输入 Grid。最终当然仍有一个可执行的输入到输出函数，但合成问题已分解为独立特征运输与剩余特征构造，不要求所有输出对象都有输入对象对应物。

## 通用指称约束

可用指称包括：唯一物体、唯一指定颜色物体，以及全体或指定颜色物体中的最左／最右／最上／最下物体。极值并列时返回歧义，缺失时返回错误，绝不按 object ID、扫描顺序或首个样例偷偷消歧。五种几何锚点为 TL/TR/BL/BR/Center。

P 必须闭合且类型为 `Ti -> Ti`；只允许标量字面量，不允许原始坐标、向量、对象、场景或集合字面量。由纯常量拼出的闭合几何表达式也被拒绝。`index/head/tail/get/argminBy/argmaxBy` 被此入口的保守策略排除，避免下标或稳定排序的隐含案例身份。显式语义极值选择由带唯一性检查的 `Selection` 执行。

这些检查保证训练案例上指称有定义，并在新案例上显式报告缺失或歧义；它们不是对任意可能场景的总函数证明，也不能从有限样例证明规则的真实泛化性。

## Output-wise witness 与执行时依赖

`outputWitness :: Int -> [Scene] -> (Maybe Recipe, Int, String)` 一次接收全部训练输出，不接收输入。它为每个跨案例语义角色寻找共同构造规则，并要求所有输出物体均被恰好覆盖。候选必须在所有输出中回代成立。

当前构造语法支持：

- 跨所有输出共享的标量常量。
- 实心、单色矩形（包括单像素）。
- 宽高来自输出画布宽高，或跨案例共享的整数常量。
- 物体的角点／中点与输出画布的角点／中点对齐。位置由每个案例的尺寸重新计算，不记录训练坐标。

训练时 witness 可以观察完整 O；预测时 `Rectangles` 只能读取已经解码的输出宽高。固定依赖顺序为宽、高、背景、物体列表。缺少依赖或尺寸／位置越界时失败，不读取未知 O，不用训练值填洞，也不求解循环依赖。

## 预算与边界

变换预算按候选在案例向量上的函数求值次数计数；每次检查完整向量前预留费用，不允许超出硬上限。1B 最多使用一半，2B 可使用余下全部预算。已找到的 P 在 2B 重验也计费。1A/2A、基础表示提取与最终网格验证属于确定性开销，不计入该搜索预算。

第三阶段有独立预算，角色检查与矩形候选的全案例验证均计费。变换阶段达到预算，或当前有限程序语法已穷尽时，进入第三阶段；不为耗尽数值预算而重复无用搜索。预算不足以检查完整向量时直接停止该搜索。

默认子程序库只提供整数加减乘、颜色常量、对象列表逐项 D4/Recolor，以及有深度界的组合。`synthesize` 接受额外的 Base Expr 库并统一检查；尚未接入 R2 的任务内 invention 发现器。这里不声称保持 R2 的求解覆盖率。

当前 decoder 以整个物体列表为一个必需特征，尚未做逐对象、形状／姿态分别对齐；第三阶段不支持任意稀疏形状、遮挡、对象间递归关系或可变数量的生成规则。失败报告为有界搜索未解决，不能推断任务不可解。构造角色的选择是有限贪心覆盖，不是完备搜索。

输出文件：`feature_trace.txt` 记录阶段、规则、未解特征、预算和预测失败原因；`predictions.json` 按测试输入顺序保存预测，无法预测时为 `null`。测试 output 不参与合成或预测。
